# Unselected compiler command and environment seam

This source unit preserves the legacy runner and supplies pure command/environment helpers plus an unselected wordcount planner. It configures no image profiles and performs no compiler, image, Docker, provider or source-data action at import. Neither a returned plan nor a supplied profile object grants execution authority.

`LatexCommand.ts` is the actual legacy latexmk builder extracted into strict erasable TypeScript. `LatexRunner` delegates with the same default `$COMPILE_DIR`, engine/flag order, prefixes, strace, halt/force and historical knit-extension naming conversion. `CompileManager` shares its generated project/chktex environment constructor while preserving its existing image-variant selection and fallback. Candidate contexts change only constructed directory/tool slots, preserving literal filename/flag text; they do not globally replace tokens.

`CompileEnvironment.ts` shares the finite three generic and eleven compile metadata keys and value/control/size checks. Generic jobs retain their three-key/default policy. Known numeric1 switches normalize explicitly; arbitrary objects/numbers do not become strings. Protected HOME/PATH/TEXMF/CLSI never come from request overrides. The concrete trusted legacy defaults HOME=/tmp, TEXMFVAR=/tmp/texmf-var, TEXMFCONFIG=/tmp/texmf-config and numeric CLSI1 are recognized. New selected-profile jobs deliberately use HOME=/home/tex, those two bounded temp paths, CLSI=1 and the trusted profile's TeX binary directory in PATH; this is an explicit HOME difference, not exact environment parity. Digests never infer a TeX year.

`CompilerCommandPlan.ts` requires a genuine active scope from its exact owning manager. The copied scope metadata supplies project identity. Its wordcount plan contains immutable image/argv/cwd/environment/profile selection, project ID and60000ms deadline, with no host input/output paths and no execution port. Final validation independently retains its /compile working directory and60000ms operation bound. Trusted profile inventories freeze configured immutable pins, aliases, variants and absolute tool facts, rejecting contradictory bindings. There are no built-in/native-qualified profiles. Unknown top-level planner settings and unsupported required tool/prefix bindings refuse. Nested trusted profile/tool objects are not closed-schema validated: extra profile fields are ignored and extra tool keys remain unused. They grant no additional command or execution capability.

Compile-plan issuance refuses because a genuine bounded source/transform/TikZ-preparation authority does not exist. The selected-profile final job validator independently refuses hand-built latexmk requests; a profile ID cannot bypass that boundary. Configured compiler image digests also require explicit profile selection, including equivalent pin spellings; omitting the selector cannot downgrade them into generic policy. Unconfigured generic images retain their existing behavior. Pure argv compatibility tests are not issued compile plans or native compiler acceptance. Generic existing jobs are unchanged. Optional strace/log/PDF-worker/qpdf/cache publication profiles remain unsupported under their existing contracts. No plan-to-job bridge or legacy main-runtime selection is added.

The job adapter snapshots caller fields/getters and nested arrays/environment before its first await, freezes trusted policy facts, and captures the final approved environment once. Create and exec consume copies of that same captured value. Admission uses the shared finite policy, retains bounded selector metadata and requires carried project identity to match its real workflow. Existing600000ms compile/30000ms queue limits, source-cache preclaims, workspace/cleanup ownership and completed-artifact revision remain intact.

The existing compiler regression and strict type/native gates expand through their current package/configuration entrypoints; all ten original LatexRunner cases remain selected. New legacy-graph regressions are strict TypeScript in the existing source-input gate, keeping its checkJs:false scope for unchanged legacy JavaScript. New production modules and remaining new tests are in the stricter archive gate. All19 hook IDs and matching CI entrypoints remain unchanged. Actual hooks/CI and any future native-image tool/environment/content proof belong to later reviewed adoption and activation gates.
